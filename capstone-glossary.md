# GA capstone glossary

Use this page when you need a reminder. Each project part also explains its key terms where you use them.

| Term | Plain-English meaning |
| --- | --- |
| **Capstone** | A project that brings together the skills you learned during the program. |
| **Deliverable** | Work you submit, such as a slide deck, dataset, or notebook. |
| **Rubric** | The criteria and scoring scale used to assess your work. |
| **Portfolio / portfolio-ready** | A collection of work you can show to employers or collaborators / work clear, complete, and well explained enough to include in it. |
| **Pitch** | A brief explanation of an idea and why it is worth exploring. |
| **Lightning talk** | A short, focused presentation. For Part 1, the whole talk lasts 3–4 minutes. |
| **Slide deck** | The set of slides used for a presentation. |
| **Problem statement** | A clear description of the question or problem you will investigate. |
| **Potential audience** | People who could use or care about your findings. |
| **Goals / specific aim** | What you want to achieve / a precise statement of the result you are working toward. |
| **Success criteria / success metrics** | What counts as success / the measures you use to assess it. |
| **Data acquisition** | Finding and obtaining the data you need. |
| **Data munging** | Changing the structure or format of data so you can analyze it. |
| **Data cleaning** | Checking and handling errors, duplicates, missing values, and inconsistent entries. |
| **Data dictionary** | A table explaining each column and its type or format. |
| **Exploratory data analysis (EDA)** | Using summaries and charts to understand the data and identify patterns or problems. |
| **Descriptive and visual analysis** | Describing data with numerical summaries and charts. |
| **Variables of interest / features** | Variables relevant to your question / inputs used by a model. |
| **Outlier** | A value far from most others. Check whether it is an error or a real case. |
| **Data imputation** | Filling in missing values using an explained method. |
| **Progress report** | A brief account of what you tried, found, and plan to do next. |
| **Roadblock / setback** | A problem preventing progress / a difficulty that delays or changes your plan. |
| **Model selection / implementation / evaluation** | Choosing a method / building and running it / checking how well it works. |
| **Baseline** | A simple method or result used as a point of comparison. |
| **Prediction / inference** | An estimate for a new case / a conclusion drawn from analysis. Inference alone does not establish cause and effect. |
| **Executive summary** | A brief overview of the goal, metrics, findings, and important risks or limits. |
| **Technical stakeholders** | People who need to understand or review the technical work. |
| **Reproducible results** | Results another person can obtain by following your steps with the same data and setup. |
| **Technical appendix** | Supporting details, source links, or code placed after the main report. |
| **Assumptions / risks / limitations** | Conditions you rely on / things that could go wrong / boundaries on what the results can tell you. |
| **Non-technical summary** | An explanation for people who may not know data science. |
| **Data storytelling** | Connecting the question, evidence, and findings so the audience can follow your explanation. |
| **Deployment / production** | Making a model available to users / operating it in a real service or workflow. |
| **Bonus** | An optional extension beyond the required work. |

These terms follow the [original GA capstone repository](https://github.com/ga-curriculum/dsb-capstone), with short explanations for this class. The [README](./README.md#your-path-through-the-project) links to each deliverable.
